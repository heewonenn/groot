# Hackathon pitch

Read the project README, actual application flow, evaluation artifacts, and current readiness report. Use the intended audience and time limit if supplied; otherwise make a concise, explicitly stated assumption.

Structure the story around the user's problem, the implemented solution, a concrete demo, evidence of value, the architecture, and limitations or next steps. Explain the purpose of each major component in everyday language. Distinguish implemented functionality from planned work and local prototypes from deployed services.

Use only traceable measured ML results. Include metric definition, held-out evaluation context, dataset size, and a baseline when available. If measurements are absent, say they are pending and describe the verification plan; do not invent accuracy, usage, testimonials, speed, or business impact.

Write a timed demo script with exact actions, expected observable outcomes, and a fallback using previously verified functionality. Avoid private records and credentials in screenshots or examples. An outline does not authorize creating external presentation files, publishing, or messaging teammates.

Verify every factual claim against project evidence and walk through the demo steps when executable. Deliver the outline or script requested, supporting evidence references, known limitations, and any rehearsal steps that remain untested.
