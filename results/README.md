# Сдача результатов команды WE ARE GROOT

В Git должны появиться два файла формата организаторов — `results/dev/results.json` для 60 чатов и 5 звонков и `results/prod/results.json` для 10 контрольных чатов. Каждый файл создаётся после обработки соответствующего набора. Доступ к контролю выдаётся через 23 часа после старта. До стоп-кода остаётся час на импорт, оценку, проверку и push.

Команды ниже выполняются **из корня репозитория**. CLI использует ту же локальную SQLite, что и сервер. Если сервер запускается с `CQA_DB_PATH`, задайте то же значение в терминале экспорта. Посмотреть доступные задания DEV:

```powershell
$python = '.\.venv\Scripts\python.exe'
& $python -m backend.app.submission status dev
```

## Контроль команды на Gemma 4

Когда организаторы выдадут группу, запустите модельный API и выполните:

```powershell
$group = Read-Host 'Точный group_id от организаторов'
.\.venv\Scripts\python.exe -m scripts.run_control --group-id $group
.\.venv\Scripts\python.exe -m backend.app.submission check prod --group-id $group
```

Первый вызов импортирует группу и запускает до двух чатов одновременно на Google Gemma 4 31B.
После десяти исходных попыток сохраняет JSON, повторяет технические ошибки один раз и обновляет
файл. При повторном запуске с тем же ID использует готовые оценки. Код завершения 0 означает,
что выгрузка содержит десять успешных оценок. При ненулевом коде проверьте сообщение команды.
Порядок публикации и ссылки для защиты приведены в [плане команды](../docs/PARTICIPANT_2_4_PLAN.md).

## Когда задания уже запущены

Укажите исходные ID заданий для чатов и звонков. Экспортёр проследит дочерние повторы, проверит охват всех диалогов и возьмёт название модели из сохранённых результатов. Режим укажите по фактическому способу работы модели — `local`, `external_api` или `hybrid`.

```powershell
& $python -m backend.app.submission export dev --mode $mode --job $chatJob --job $callJob
& $python -m backend.app.submission check dev
```

## Когда набор нужно обработать с нуля

Запустите общий API на 8765 с реальным адаптером участника № 2. Сначала проверьте DEV. На контрольном этапе используйте выданный организаторами ID группы:

```powershell
$python = '.\.venv\Scripts\python.exe'
$group = Read-Host 'Выданный group_id'
$model = Read-Host 'Фактический ID подключённой модели'
$mode = Read-Host 'Режим модели (local, external_api, hybrid)'
$id = [uri]::EscapeDataString($group)
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8765/api/groups/$id/import"
& $python -m backend.app.submission run prod --group-id $group --model $model --mode $mode
if ($LASTEXITCODE -eq 0) {
    & $python -m backend.app.submission check prod --group-id $group
}
```

Для DEV команда — `run dev --model $model --mode $mode --compact`. Для контрольного набора тот же флаг можно добавить к `run prod`. Модель выбирает ответ из шкалы каждого критерия и указывает первый и последний номера реплик с единицы. Сервер восстанавливает исходные идентификаторы, проверяет доказательства и считает баллы. Число одновременно обрабатываемых диалогов задаёт `CQA_EVALUATION_WORKERS` (1–8, по умолчанию 4).

Чаты и звонки запускаются по своим исходным чек-листам. Повтор той же команды с теми же параметрами и `--run-key` продолжает ожидание сохранённых заданий. По умолчанию CLI ждёт до 45 минут. Время ожидания можно изменить через `--wait-minutes`. По истечении времени задания остаются в очереди. Для повторной обработки неуспешных записей используйте `POST /api/evaluation-jobs/{id}/retry` с новым `Idempotency-Key`, затем экспортируйте по исходному ID.

## Что попадает в файл

- Восемь кодов критериев — `contact`, `discovery`, `identification`, `consultation`, `empathy`, `dialogue`, `closure`, `critical`.
- Публикуются исходные ответы автоматической оценки, краткие обоснования и номера подтверждающих реплик с единицы по полному транскрипту. Оценка по числовой шкале остаётся в исходных единицах. Итог сверяется с общим калькулятором. Флаг грубой ошибки хранится отдельно.
- Если после реальной попытки ответ получить не удалось, ID остаётся в файле со статусом `error`, пустым массивом `criteria`, `score: null` и причиной. Валидация выполняется до замены рабочего файла. Обе команды выводят число успешных и неуспешных записей.

## Перед стоп-кодом

Проверьте оба файла, просмотрите обоснования на предмет приватных данных и передайте жюри результаты в публичной ветке командного репозитория. Отправлять DEV можно заранее. Для одновременной публикации двух готовых файлов:

```powershell
git add -- results/dev/results.json results/prod/results.json
git diff --cached --stat
git commit -m "Submit DEV and control evaluation results"
git push
```

При работе через pull request убедитесь, что оба файла доступны по ссылке на ветку сдачи, которую получили организаторы. Если им передана страница репозитория на `main`, завершите слияние до стоп-кода.
