# Участница №3: репетиция карточки и апелляции

Сценарий подготовлен 08.11.2026 для общей сборки `main` на базе `0bf2f83`.
PR №5 участницы №3 и PR №11 участника №2 уже объединены в `main`.
Цель показа — доказательства, пересмотр и сохранение истории. Смысловая точность
модели этим сценарием не измеряется.

Сценарий может полностью выполнить один человек. Присутствие участника №4
не требуется: импорт, хранение и расчёт подключены программно. Формулировка
«№3 вместе с №4» в командном плане распределяет выступление, а не вводит
дополнительное подтверждение в приложении. Для реальных сохранённых карточек
нужны соответствующая база команды и аудио; достаточно любого уполномоченного
человека, у которого есть доступ к ним и компьютеру защиты.

## Отдельная база для репетиции на Windows

Зависимости устанавливаются по [инструкции запуска](PARTICIPANT_3_GUIDE.md).
Не удаляйте и не подменяйте общую базу команды. В первом терминале PowerShell,
из корня актуального проекта, выполните:

```powershell
$env:CQA_DB_PATH = Join-Path (Get-Location).Path 'data/participant3-rehearsal.sqlite3'
$env:CQA_MODEL_ENABLED = '0'
.\.venv\Scripts\python.exe -m backend.app.participant3_demo
.\.venv\Scripts\python.exe -m uvicorn backend.app.model_app:create_configured_app --factory --host 127.0.0.1 --port 8765
```

В другом терминале из корня проекта:

```powershell
cd frontend
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Откройте:

<http://127.0.0.1:5173/analysis?group_id=SYNTHETIC&conversation_id=synthetic-contract-001&evaluation_id=demo-synthetic-contract-001>

Это искусственные данные с отключённой моделью. Если порт занят, остановите
свой прежний сервер через Ctrl+C; не запускайте две сборки на тех же портах.
Повторное добавление примеров сохраняет апелляции. Для повторного показа
перехода с исходных 85,38 используйте новый файл, например
`data/participant3-rehearsal-2.sqlite3`, а не удаление базы команды.

## Последовательность показа

1. Убедитесь, что видны «Демонстрационный пример» и исходные 85,38.
2. Откройте критерий 04 «Консультация», нажмите «Перейти к фрагменту».
   Выделяется `synthetic-contract-001:m0006` в группе `SYNTHETIC`.
3. Нажмите «Оспорить оценку». В комментарии напишите:
   «Учебный пересмотр критерия 04 для демонстрации сохранения истории».
4. Нажмите «Сохранить обращение», выберите «Изменить ответ», новое значение 20.
5. Укажите обоснование: «Учебное изменение ступени с 15 на 20 по сохранённой
   версии правил; не разметка DEV». Проверьте привязанную реплику.
6. Нажмите «Применить решение». Итог становится 93,08; исходные 85,38 остаются.
   Это проверка арифметики общего модуля №1, не результат живой модели.
7. Нажмите F5. В «Истории проверки» проверьте переход 15 → 20 и обоснование.
   Раскройте «Обращение и доказательства»: комментарий и message_id сохранены.
8. «Скачать отчёт карточки» сохраняет внутренний отчёт с оригиналом и историей.
   «Экспорт для сдачи» — другой процесс; учебная группа не проходит официальную сдачу.

## Текст выступления на 60–90 секунд

«Моя часть — карточка оценки и апелляции. Здесь видны исходный диалог,
критерии, причины и доказательства. Показываю на искусственном учебном примере.

Выбираю консультацию и перехожу к подтверждающей реплике. Связь хранится
через группу, диалог и message_id, поэтому одинаковое время не смешивает сообщения.

Сохраняю обращение, меняю ответ и обосновываю решение. Общий модуль участника №1
пересчитывает итог по исходной версии чек-листа. В учебном примере изменение
15 на 20 даёт 93,08 вместо 85,38. Оригинал сохраняется отдельно.

Обновляю страницу: решение, комментарий и доказательства остались в истории.
Отчёт карточки содержит оригинал и пересмотр. Это демонстрация работы программы;
точность модели по этим числам оценивать нельзя».

## Что остаётся участнице №3

- Согласовать с №1 оставшиеся трактовки 02, 04, 05 и 07 из предварительного
  разбора. По 06 настоящего звонка учесть уже зафиксированное решение ниже.
- Передать №2 исправления и результаты личной проверки. Черновик ChatGPT
  остаётся ассистированным; независимые человеческие оценки нужны отдельно.
- Пока для английской апелляции нет прямого официального подтверждения правила
  закрытого счёта, сохранить её открытой с объяснением. В интерфейсе можно
  сохранить обращение, закрыть окно и вернуться к нему после F5 без решения.
  Здесь статус настоящего обращения в общей базе не изменяется.
- Отрепетировать свой показ: доказательство → комментарий → решение → пересчёт
  → F5 → история. Для показа достаточно отдельной учебной базы выше.

Подготовка компьютера защиты, резервная копия общей базы, импорт контрольной
группы и официальная сдача остаются участнику №4. Настройка модели и её квота
относятся к участнику №2 совместно с №4. В работу №3 здесь входят карточка,
доказательства, апелляции, история и подготовка собственного выступления.

закрытого счёта по-прежнему не зафиксировано. Этот вопрос остаётся открытым.
