## Настоящий браузер и общий сервер

Chromium `/usr/bin/chromium` запущен через Playwright с настоящим FastAPI на
8765, Vite на 5173 и одноразовой SQLite. Для интеграции №3 сервер получил
`CQA_E2E_PARTICIPANT3=1` и явно создал пять синтетических карточек.
Старые тесты запущены отдельно без этой переменной, чтобы сохранить их исходный
набор из одного диалога. В стандартном Windows-скрипте первый проход намеренно
пропускает сценарии №3, затем отдельный проход выполняет их с явным demo-набором.
Во втором, окончательном запуске всех проверяемых браузерных сценариев пропусков нет.

Проверено через интерфейс и сохранённые ответы настоящего API:

- Апелляция критерия 04: 15 → 20, итог 85,38 → 93,08. После перезагрузки
  сохраняются результат, исходный ответ и исходный итог 85,38.
- Грубая ошибка отмечается отдельно и не уменьшает числовой итог. N/A по 07
  исключает вес из расчёта; после предыдущего пересмотра итог равен 92,50,
  применимый вес — 60. Внутренний JSON-отчёт скачивается и содержит оригинал,
  итог и три решения.
- Неопределённый AI-ответ разрешается человеком. Числовой итог появляется
  только после разрешения; исходный AI-статус остаётся partial, исходный итог —
  null. История показывает «Не определён → Да», а не подменяет неизвестность N/A.
- Официальный экспорт неполного demo-набора возвращает 422 и не скачивает
  фиктивный results.json. Успешный формат DEV/PROD и запрет demo-ответов
  проверены серверными тестами на искусственных полных наборах.
- Ошибка загрузки карточки восстанавливается после повтора с клавиатуры.
  Казахский текст отображается; при ширине 360 px горизонтального переполнения нет.
- Сообщения bot и system с одинаковым timestamp выбираются по разным message_id.
  Ссылка на доказательство проходит маршрут исходной реплики, выделение и URL
  восстанавливаются после перезагрузки.
- Для звонка без записи показывается честное состояние «Запись звонка недоступна».
  Плеер и позиции не выдумываются.

Десктопные и мобильные снимки интерфейса визуально проверены.
В сценариях №3, собирающих ошибки JavaScript, необработанных ошибок не возникло.
После небольшой правки сохранения контекста повторён затронутый сценарий:
после решений по 04, 08 и 07 соответствующий критерий остаётся выбранным,
пересчёт, перезагрузка и скачивание отчёта проходят. Lint и production-сборка
повторно пройдены после этой правки.

Исходный тест №4 проигрывания сначала выявил неточную заглушку: она игнорировала
HTTP Range, и Chromium не мог перемотать поток WAV. Изолированный браузерный
пример подтвердил, что корректный ответ 206 с Content-Range и Accept-Ranges
устраняет проблему без изменения плеера. Исправлена только заглушка теста;
повторно проверены перемотка к 3,25 секунды и обработка недоступной записи.
Настоящий аудиопрокси №4 уже поддерживает Range.

## Приватный статический предпросмотр

Он использует тот же React-интерфейс и отдельный demo-транспорт.
Для транспорта отдельно выполнены 7 Node-тестов и настоящий запрос через
Axios fetch-адаптер. Подсчёты demo предварительно получены общим Python-модулем №1.
Веб-предпросмотр не запускает SQLite и не выполняет модель.

Доступный здесь preview relay и инструменты браузера приватного хостинга
не позволили проверить опубликованный адрес в пользовательском браузере.
Прохождение локальных браузерных тестов не заявляется как браузерная проверка
развёрнутого сайта; статус публикации проверяется отдельно средствами Sites.

## Оставшиеся зависимости

- Адаптер настоящей модели участника №2 пока не передан. Платные AI API
  не вызывались; качество оценки новых диалогов не проверялось.
- DEV/PROD организаторов и реальные записи звонков не использовались.
  Проигрывание и перемотка проверены на искусственном WAV с явно заданными
  проверенными позициями, без утверждений о качестве реального распознавания.
- Приватное браузерное хранилище предпросмотра не является SQLite общего сервера.
  Совместная работа требует запуска полной сборки и подключения модуля №2.
