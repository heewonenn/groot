# Общая сборка по CQA team ZIP

По указанию пользователя от 7 ноября 2026 года проект использует привязки, общий чат и сервер из `CQA-team.zip`. Это действующая основа интеграции для четырёх участников. Требования организаторов, восемь исходных критериев, версии чек-листов и единый расчёт сохраняются.

## Принятые значения

| Настройка | Действующее значение |
| --- | --- |
| Общий backend | `http://127.0.0.1:8765` |
| Frontend | `http://127.0.0.1:5173` |
| Общий чат | `DEV / p1-ru-001`, 12 сообщений |
| Общий звонок | `DEV / p4-ru-001`, 45 сообщений |
| Первая реплика оператора общего чата | `p1-ru-001:m0010` |
| Массив реплик | `transcript` |
| Ссылка на доказательство | `group_id + conversation_id + message_id` |
| Нумерация | С единицы в полном исходном массиве, до фильтрации ролей |
| Изменение уже импортированного диалога в той же группе | 409 и откат всей загрузки; прежние данные сохраняются |
| Изменение правил оценки | Новая неизменяемая версия чек-листа, как прежде |

Действующая схема — [cqa-team-v1.schema.json](contracts/cqa-team-v1.schema.json), описание — [общий контракт](contracts/README.md). Старый вариант схемы и искусственных примеров находится в `docs/contracts/legacy`; его не использовать для новых модулей. Локальные примеры ZIP находятся в `data/examples/team-zip-v1`, старые подготовительные данные оставлены отдельно.

## Что объединено

Код импорта и чтения диалогов из `04-api/app.py` перенесён в `backend/app/team_data.py` и подключён к общему `backend/app/main.py` как router. Пути, поля, message_id и политика конфликтов ZIP сохранены. Адаптация состоит в общей базе, подключении рядом с чек-листами, типизации, форматировании и безопасном сообщении при ошибке SQLite. Это не второй независимый сервер.

Таблицы данных — `groups` и `conversations`; таблицы участника 1 — `cqa_checklists` и `cqa_checklist_versions`. По умолчанию все находятся в `data/cqa.sqlite3`; путь меняется через `CQA_DB_PATH`. Перенос не переписывает чек-листы. Для локального снимка добавлена команда `backend.app.import_snapshot`, которая использует ту же валидацию и политику конфликтов.

Vite, Playwright, задачи VS Code, README, ТЗ и инструкции участника 1 переведены на порт 8765. Новые зависимости не добавлялись. Исходные тесты ZIP перенесены и дополнены проверкой общей базы, отсутствия утечки ошибок и сохранения query-подписи.

## Запуск

Из корня проекта в первом PowerShell:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8765
```

Во втором терминале:

```powershell
cd frontend
npm run dev
```

Редактор — [localhost:5173/checklists](http://127.0.0.1:5173/checklists), документация общего сервера — [localhost:8765/docs](http://127.0.0.1:8765/docs).

Для общей сборки используется этот запуск. Архивный `start.py` запускает самостоятельный модуль данных; одновременно занимать им тот же порт не требуется.

## Доступ к данным

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/api/groups/{group_id}/import` | Первый или повторный импорт группы |
| GET | `/api/groups/{group_id}/conversations` | Список; фильтры language и channel |
| GET | `/api/groups/{group_id}/conversations/{conversation_id}` | Карточка данных с transcript и audio_url |
| GET | `/api/groups/{group_id}/conversations/{conversation_id}/messages/{message_id}` | Одна реплика по составной ссылке |
| GET | `/api/checklist-versions/{version_id}` | Сохранённая конфигурация чек-листа |
| POST | `/api/checklist-versions/{version_id}/calculate` | Общий расчёт ответов по выбранным правилам |

Пример доказательства из ZIP:

```json
{"group_id":"DEV","conversation_id":"p1-ru-001","message_id":"p1-ru-001:m0010"}
```

Ссылка открывается через [общий API](http://127.0.0.1:8765/api/groups/DEV/conversations/p1-ru-001/messages/p1-ru-001:m0010). Модель должна возвращать все три поля. Карточка ищет message_id в transcript, сохраняя группу и диалог. При апелляции дополнительно сохраняется исходный checklist_version_id.

Полный model_result/evaluation_response в общей схеме расширяет одно-критериальный пример ZIP до всех критериев, причин N/A, диапазонов доказательств и истории пересмотра. Этот формат подготовлен для участников 2 и 3; реальный оценщик и обработчик апелляций ещё не подключены.

## Источник и локальная база

На данном компьютере предоставленная пользователем ссылка импорта сохранена в игнорируемом файле `data/team-api/source_url.txt`. Её содержимое не переносится в Git. Альтернатива — переменная процесса `CQA_SOURCE_URL`, имеющая приоритет. На другом компьютере участник задаёт свою разрешённую настройку источника. `.env` автоматически не загружается.

В базу загружены 65 записей из ранее полученного DEV. Затем выполнен настоящий повторный импорт через новый endpoint: HTTP 200, inserted=0, unchanged=65. Это проверка данных, не запуск AI. Для контроля нужно использовать выданный организаторами group_id; неизвестная контрольная группа заранее не проверялась.

Для восстановления из собственного локального снимка без сети:

```powershell
.\.venv\Scripts\python.exe -m backend.app.import_snapshot data/raw/cqa_dev_2026-11-07.json --group-id DEV
```

Если та же группа уже содержит изменённые относительно снимка диалоги, команда завершится с конфликтом; прежняя база не перезаписывается. Примеры DEV, база и источник остаются в исключённом из Git каталоге data. Публичные тестовые примеры искусственные и помечены как demo.

## Проверенный объём и ограничения

- Транскрипты и все message_id общего чата и звонка совпали с JSON из ZIP.
- Настоящий GET источника через endpoint импорта вернул те же 65 записей без дублей.
- В том же приложении открываются реплика p1-ru-001:m0010 и freedom-chat@1.
- 10 новых серверных проверок прошли: контракт, группы, повтор, конфликт и откат, сохранность чек-листов, арифметика и сообщения ошибок.
- Полная проверка `pwsh -NoProfile -File scripts/verify.ps1` завершилась с кодом 0: **35 Python-тестов, 7 браузерных тестов**, зависимости, Ruff, ESLint, TypeScript и Vite прошли. Браузер работал с настоящим общим сервером на 8765; отдельно проверена цепочка Vite → API данных → message_id и работа калькулятора в том же приложении.

Браузерные проверки используют временную базу и искусственный диалог SYNTHETIC; пользовательский DEV не изменяют. Live-импорт проверен отдельно. Политика ошибок ZIP сохраняет `{"detail":"..."}`, чек-листы используют `{"error":{...}}` — клиенту данных нужно учитывать оба формата.

Автоматической оценки моделью, карточки пользователя, апелляций и пакетной оценки пока нет. API предоставляет audio_url, который может вести на HTML-плеер; точный переход к фразе не реализован. Два сопоставления аудио, описанные автором ZIP, при этой интеграции не перепроверялись прослушиванием. Свежая установка на другом компьютере и production-развёртывание также остаются задачами приёмки.
