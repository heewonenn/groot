## Что работает в одной программе

- Получение диалога и исходных `message_id` из сервера ZIP.
- Выбор опубликованной неизменяемой версии по поддерживаемому каналу.
  Правка каналов черновика не скрывает ранее сохранённые версии.
- Явный запуск новой оценки через очередь участника 4 и `ModelEvaluator`
  участника 2. Готовность берётся из `/api/model-status`.
- Прогресс, ошибки, повтор неуспешного задания и восстановление просмотра
  задания после обновления страницы. Обновление страницы не запускает inference.
- Открытие новой карточки, исходных причин и доказательств; история старых
  оценок сохраняется, выбранная старая оценка не заменяется новой при reload.
- Метаданные точного запуска: версия инструкции/справочника, попытки,
  задержки, токены, известная оценка стоимости в USD. Если данных нет, это
  неизвестное значение, а не ноль. Учебные показатели явно обозначены.
- Цитаты из сохранённого входа модели, переход к исходным репликам и диапазонам.
- Апелляция, решение, общий пересчёт участника 1, неизменный оригинал AI и
  исходная версия правил, сохранение после перезапуска и внутренний JSON-отчёт.
- Официальный `results.json` остаётся отдельным экспортом исходных AI-ответов
  по PDF. Частичные/ошибочные попытки не исчезают из полного набора.

Статус failed-задания содержит общий код очереди. История запусков по диалогу
показывается отдельно, с собственными evaluation_id и временем: в текущем
контракте №4 потерпевший ошибку item не сохраняет evaluation_id. Нельзя
приписать ему произвольно последний запуск другого задания.

## Запуск сейчас, пока модель не выбрана

После [установки зависимостей](PARTICIPANT_3_GUIDE.md) запустите один backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.model_app:create_configured_app --factory --reload --host 127.0.0.1 --port 8765
```

Во втором терминале:

```powershell
cd frontend
npm run dev -- --port 5173 --strictPort
```

Откройте <http://127.0.0.1:5173/analysis>. Сохранённые карточки и апелляции
доступны; «Оценить диалог» выключена, пока сервис не настроен. Для искусственных
карточек один раз выполните из корня `python -m backend.app.participant3_demo`
через `.venv\Scripts\python.exe`. Они не заменяют настоящие ответы модели.

Не запускайте второй сервер на 8765. Если интерфейс пишет, что нет маршрутов
модели, остановите прежний `main:app` и используйте factory выше.
VS Code task `Backend: dev` уже использует этот factory.

## Когда команда выберет модель

Участник 2 должен подтвердить поддерживаемый сервис, точный ID модели,
размер контекста, бюджет и продуктовые материалы. Сейчас реализован адаптер
OpenAI Responses со Structured Outputs; другой сервис требует собственного
Provider. Не надо выбирать модель только потому, что её название есть в примере.

Серверные настройки описаны в [handoff участника 2](PARTICIPANT_2_HANDOFF.md).
Ключ вводится локально/в настройках окружения, не в чат и не во frontend.
`.env` автоматически не читается. Без подтверждённых тарифов стоимость остаётся
неизвестной. Настройка не отправляет диалоги: запрос создаётся нажатием
«Оценить диалог» после согласования внешних вызовов.

1. Импортировать DEV по [инструкции ZIP](ZIP_INTEGRATION.md).
2. Выбрать `p1-ru-001` и сохранённую `freedom-chat@1`.
3. Убедиться, что статус модели «готова», нажать «Оценить диалог» один раз.
4. Проверить исходные ответы, обоснования, N/A, доказательства и аудит.
5. Подать апелляцию, принять решение и проверить итог после reload.
6. Перейти к `p4-ru-001`, затем RU/KZ/EN и всему набору.
7. Изменённый и новый критерий проверять настоящим повторным запуском новой
   версии. Старая карточка/апелляция остаётся на прежней версии.

Текущий адаптер оценивает транскрипт и timestamps. Наличие плеера не означает,
что модель анализировала дикцию, темп или другие акустические признаки.
Без продуктового справочника нельзя объявлять проверенной правильность тарифа.

## Изменения интеграции

Нативный `cqa-team-v1` не менялся. К обёртке карточки добавлено
`runtime.model_run` с безопасными метаданными точного запуска; при отсутствии
аудита — null. Чтение идёт в существующей SQLite-транзакции без создания
второго RunStore и без переноса приватного снимка входа в ответ карточки.

В factory участника 2 исправлено восстановление истории после сбоя:
оно выполняется и при выключенной/ненастроенной модели. Зависший аудит
становится interrupted, как и очередь; автоматического повторного вызова нет.
При недоступной SQLite health остаётся доступен.

Результаты проверок и ограничения — [QA](PARTICIPANT_3_MODEL_QA.md).
Реальная модель пока не выбрана пользователем: внешних платных запросов,
проверенного качества AI, фактической стоимости и настоящего DEV/PROD-прогона
эта поставка не заявляет.
