# Участник 3: запуск и передача модуля

Эта локальная сборка основана на `main` 98eb692 и ветке участника 4
6c55306. Она добавляет рабочее место контроля качества и апелляции.
Изменения не отправлялись в GitHub. Не заменяйте рабочую папку другого
участника целым архивом: сначала сохраните свою работу и сравните изменения.

## Первый запуск на Windows 10/11

Нужны Git, VS Code, Python **3.14**, Node.js **24 LTS** и PowerShell **7**
(`pwsh`). Уже установленные программы переустанавливать не требуется.
Официальные установщики: [Git](https://git-scm.com/downloads/win),
[VS Code](https://code.visualstudio.com/), [Python](https://www.python.org/downloads/windows/),
[Node.js](https://nodejs.org/),
[PowerShell](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows).

1. Распакуйте архив в отдельную папку, например `C:\Projects\CQA-participant-3`.
   Откройте именно эту папку в VS Code, где находятся `README.md`, `backend`
   и `frontend`. Архив не содержит `.venv`, `node_modules`, данных DEV или ключей.
2. В терминале PowerShell из корня выполните:

   ```powershell
   pwsh -NoProfile -File scripts/setup.ps1
   ```

   Скрипт устанавливает зависимости из lockfiles и браузеры для проверок.
   В VS Code выберите интерпретатор `.venv\Scripts\python.exe`.
3. Для проверки своей карточки без модели добавьте искусственные примеры:

   ```powershell
   .\.venv\Scripts\python.exe -m backend.app.participant3_demo
   ```

   Это отдельная явная команда, а не имитация подключённой модели. Она добавляет
   RU/KZ/EN, звонок без записи и частичный ответ в группу `SYNTHETIC`.
   Повторный запуск сохраняет существующие решения. Данные находятся в SQLite
   `data/cqa.sqlite3`; не удаляйте этот файл, если нужна история апелляций.
4. Запустите backend в первом терминале:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8765
   ```

5. Откройте второй терминал из корня и запустите frontend:

   ```powershell
   cd frontend
   npm run dev -- --port 5173 --strictPort
   ```

6. Откройте [учебную карточку](http://127.0.0.1:5173/analysis?group_id=SYNTHETIC&conversation_id=synthetic-contract-001).
   API: <http://127.0.0.1:8765/docs>. Оба терминала должны работать;
   остановка — `Ctrl+C`. Предпросмотр HTML без backend не заменяет этот запуск.

Если порт занят, остановите прежний экземпляр программы. Сохраняйте согласованные
порты 8765/5173. Сообщение «Оценщик не подключён» означает отсутствие адаптера
участника 2, а не необходимость подставить демонстрационный результат.

## Проверка своего сценария

1. Выберите `synthetic-contract-001`. Метка DEMO обязательна: это не реальная
   оценка модели и не Ground Truth. Число 85,38 проверяет общую арифметику.
2. Выберите критерий «Консультация», откройте доказательство. Интерфейс выделяет
   реплику по `group_id + conversation_id + message_id`; одинаковое время
   соседних реплик не объединяет их.
3. Нажмите «Оспорить оценку», напишите комментарий и сохраните обращение.
   Проверяющий может подтвердить ответ либо выбрать разрешённое новое значение,
   указать обоснование и доказательства. Для N/A нужна отдельная причина,
   соответствующая условию исходной версии правил.
4. Измените 04 с 15 на 20. Итог станет 93,08 через общий расчёт участника 1;
   исходные 85,38 и ответ модели сохранятся. Обновите страницу и проверьте историю.
5. В `synthetic-partial-001` нельзя выдавать неопределённость за N/A или
   показывать фиктивный итог. После решения по неразрешённому критерию появляется
   финальный результат проверяющего; исходный AI-ответ остаётся частичным.
6. Отдельный флаг грубой ошибки не уменьшает числовой балл. В карточке видны
   выбранная ступень, исходный вес, баллы до перераспределения N/A и итоговый вклад.
7. Внутренний JSON-отчёт скачивает оригинал, правила и историю. Для официального
   `results.json` используется другой экспорт по [новому PDF](PARTICIPANT_3_PDF.md).
   Группа с пятью учебными примерами не является DEV/PROD и не проходит сдачу.

Запись звонка и переход к точной позиции используют компонент участника 4.
Без доступного аудио или проверенного сопоставления реплики с секундой интерфейс
сообщает об этом. Абсолютное время реплики не превращается автоматически
в смещение записи. Учебный звонок не содержит аудиозаписи.

## Что передать участникам

- Участнику 2: исходный `cqa-team-v1` не менялся. Нужен настоящий адаптер
  `create_app(evaluator=...)`, возвращающий валидированный `model_result`
  по переданным версии правил, ролям и ID. Его модуль не заменяется демо.
- Участнику 4: подключены `api.participant3.router`,
  `api.submission_downloads.router`; при запуске вызывается
  `services.participant3.initialize()`. Таблицы `cqa_p3_*` находятся в общей
  SQLite. Канонический `GET /api/evaluations/{id}` сохранён, UI получает
  дополнительную обёртку `GET /api/evaluation-cards/{id}`.
- Участнику 1: используется его неизменяемая версия и функция `calculate`.
  Новая версия чек-листа не переписывает прежнюю оценку или апелляцию.

Точный API и обработка повторов описаны в [контракте](PARTICIPANT_3_CONTRACT.md).
Проверки и оставшиеся ограничения — в [QA-отчёте](PARTICIPANT_3_QA.md).

Пути роли 3 из старого плана были целевым предложением. Чтобы сохранить
появившийся код участника 4, новые компоненты находятся в
`frontend/src/features/analysis`, серверные файлы называются `participant3.py`.
Это добавочная организация файлов, без переименования общего контракта.

Для полного сквозного испытания команда сначала импортирует настоящий
`p1-ru-001` и получает реальную оценку участника 2, затем проверяет апелляцию,
сохранение и звонок `p4-ru-001`. После этого — остальные языки и весь набор.
Прогон реальной модели, качество её ответов и проверка всех пяти записей
не подтверждаются искусственными тестами этого модуля.

## Приватный веб-предпросмотр

Он показывает интерфейс на искусственных данных и хранит решения в браузере.
В полном модуле решения хранятся на сервере в SQLite. В статическом предпросмотре
арифметика берётся из заранее рассчитанной модулем 1 таблицы для учебных правил;
произвольные новые чек-листы и настоящая модель требуют полного сервера.
Доступ к DEV и официальная сдача через этот статический сайт не выполняются.

## Проверки на своём компьютере

Остановите оба dev-сервера и выполните:

```powershell
pwsh -NoProfile -File scripts/verify.ps1
```

Проверки API используют временную базу. Для браузерных тестов роли 3:

```powershell
$env:CQA_E2E_PARTICIPANT3 = '1'
cd frontend
npm run test:e2e -- participant3.integration.spec.ts
Remove-Item Env:CQA_E2E_PARTICIPANT3
```

Тесты основной сборки запускаются без этой переменной. Не отправляйте ZIP,
патч или результаты в GitHub, пока отдельно не решите публиковать изменения.
