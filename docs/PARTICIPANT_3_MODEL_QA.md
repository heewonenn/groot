участника 3. Проверки не отправляют изменения в GitHub.

Сервис и конкретная модель командой пока не выбраны. Внешних вызовов и оплаты
в этой проверке нет. Тестовый сервер запускает настоящий `ModelEvaluator`
участника 2 и общие API, но его `SyntheticBrowserProvider.live=False` выдаёт
контролируемые ответы. Каждый полученный результат помечен `generation.mode=demo`
и исключён из оценки качества модели. Это проверка программы, а не точности AI.

## Уточнение проверки Windows

По отчёту команды на Windows прошли 229 из 230 Python-тестов и 6 subtests;
один тест недоступного хранилища завершился ошибкой. Команда также подтвердила
26 браузерных сценариев, 8 тестов demo-транспорта, Ruff, ESLint, TypeScript,
сборку и проверку зависимостей.

В `backend/tests/test_submission_downloads.py::test_storage_failure_returns_safe_503`
добавлен `tmp_path`: Unix-путь `/dev/null/http-export.sqlite3` заменён на путь
базы внутри обычного временного файла. На Windows `/dev/null` не является
специальным Unix-устройством и не гарантирует ошибку хранилища.
Такой файл не может быть родительским каталогом базы на Windows или Unix:
фикстура вызывает обрабатываемую ошибку файловой системы до открытия SQLite.
Проверки HTTP 503 и отсутствия временного пути в декодированном сообщении
ошибки сохранены, включая пути с обратными слешами Windows.
Аналогичную фикстуру использует отдельный тест доступности health/status
при недоступном хранилище. Сервер и интерфейс не изменены.
Пользователь отдельно подтвердил 503 для такого варианта на Windows;
полный Windows-прогон после исправления здесь не выполнялся.
После исправления в этой Linux-среде повторно прошли все 230 Python-тестов,
6 subtests, Ruff изменённого тестового файла и проверка diff.

## Новый сквозной сценарий

Браузер создаёт оценку нового искусственного диалога в группе `INTEGRATION`.
До запуска у него нет карточки. Запрос проходит реальную очередь участника 4,
адаптер `ModelEvaluator`, проверки ответа и доказательств участника 2,
калькулятор участника 1 и хранилище карточек участника 3.

Проверены:

- Сохранение нового `evaluation_id`, версии правил и результата; автопереход
  к готовой карточке. Исходный итог учебного примера — 85,38.
- Метаданные точно этого запуска: поставщик, модель, инструкция, время,
  попытки и токены. При учебных 100 входных и 50 выходных токенах оценка
  по заданным тестовым тарифам равна 0,0002 USD. Интерфейс подписывает её
  учебной; она не является реальным расходом.
- При неизвестном usage стоимость и токены остаются `null`, а интерфейс
  показывает неизвестность, а не нулевой расход.
- Цитаты извлекаются P2 из сохранённого входа. Переход к исходному сообщению
  проходит API реплики, выделяет правильный `message_id` и сохраняет привязку.
- Апелляция изменяет финальный итог через общий расчёт. Оригинал, модельный
  ответ и аудит запуска неизменны; обновление страницы и скачивание JSON-отчёта
  сохраняют эти различия.
- Частичный ответ P2 остаётся частичным с `original_result=null` и без
  выдуманного балла. Старые проверки №3 дополнительно подтверждают ручное
  разрешение такого ответа и отдельный финальный итог проверяющего.
- Ошибка `provider_auth` видна понятным русским текстом в истории запусков.
  Она сохраняется после перезагрузки. Повтор начинается только по явному
  действию; успешный дочерний запуск не удаляет неудачный исходный.
- Если другой проверяющий уже создал единственный retry, устаревший POST
  получает 409. Интерфейс обновляет задание GET-запросом и открывает существующий
  дочерний запуск. Второго POST или третьей попытки модели нет; устаревшая
  ошибка исчезает после открытия результата.
- При отключённом factory модель не готова, кнопка запуска заблокирована,
  причина показана, обновление статуса с клавиатуры не создаёт задания.
- После сетевой ошибки проверки готовности работает повтор с клавиатуры;
  новый блок запуска остаётся доступным при ширине 360 px.

## Версии и сохранность старых оценок

Через API участника 1 созданы три неизменяемые версии копии чек-листа.
Для каждой выполнен отдельный реальный проход **программы** `ModelEvaluator`
с контролируемым поставщиком. Изменение инструкции и добавление девятого
критерия доходят до входа адаптера, меняют его fingerprint и сохраняются
в отдельных карточках. Учебный маркер `QA_FALSE` проверяет передачу данных;
он не доказывает смысловое поведение настоящей модели.

После завершения новой оценки выбор старой карточки и перезагрузка не
переключают пользователя обратно на новое задание. Незавершённый черновик,
где канал изменён на звонок, не скрывает ранее опубликованную чатовую версию.
Апелляция старой оценки использует её исходную версию, а не этот черновик.

## Воспроизведение

Остановите dev-серверы. Штатный `scripts/verify.ps1` выполняет отдельные проходы
для исходных тестов, демо №3, подключённого тестового поставщика и отключённой
модели. Новый testserver требует явный `CQA_E2E_MODEL=1`; обычный запуск
программы никогда не выбирает этот поставщик.

Отдельные проверки на Windows после установки зависимостей:

```powershell
$env:CQA_E2E_MODEL = '1'
$env:CQA_E2E_MODEL_DISABLED = '0'
cd frontend
npm run test:e2e -- participant3-model.integration.spec.ts
$env:CQA_E2E_MODEL_DISABLED = '1'
npm run test:e2e -- participant3-model.integration.spec.ts
Remove-Item Env:CQA_E2E_MODEL, Env:CQA_E2E_MODEL_DISABLED
```

## Что ещё не проверено

Не подтверждены совместимость выбранной впоследствии внешней модели,
смысловая точность RU/KZ/EN, реальная стоимость, производительность на DEV/PROD,
настоящий повтор изменённого/нового критерия, устойчивость к prompt injection
и работа с официальным продуктовым справочником. Нужны выбранная модель,
серверная настройка доступа, согласованный бюджет и отдельный настоящий прогон.
Ключи в чат или клиентский код не передаются.

Аудио моделью не анализируется. Проигрывание/перемотка проверены прежними
сценариями на искусственном WAV; реальная синхронизация всех звонков не заявляется.
Приватный статический Sites-предпросмотр не является этим FastAPI-сервером;
его публикация и отдельный demo-транспорт проверяются отдельно владельцем задачи.
Доступные здесь инструменты не позволяют проверить опубликованный Sites-адрес
в браузере. Локальные браузерные проверки не выдаются за такую проверку;
публикация подтверждается результатом native Sites.
