# План сдачи WE ARE GROOT · участники № 2 и № 4

Мы отвечаем за модель, доказательства, данные, аудио и выгрузку. Основной результат работы — два проверенных файла в ветке, которую откроет жюри. До выдачи контроля можно закончить все шаги, кроме обработки PROD.

## С чего начинаем

На 8 ноября в локальной базе есть DEV (65 диалогов, 1 268 реплик), исходные версии для чатов и звонков и проверенные позиции для пяти записей. Первый русский чат оценён на Gemini 3.8 Flash. Успешный запуск занял 98,7 секунды, все восемь ссылок сверены с транскриптом. На предыдущей попытке сервис ответил с задержкой и временной ошибкой. Перед массовым запуском проверьте казахский и английский чаты, звонок и изменение правила. Контрольная группа пока не загружена.

| Порядок | Что делаем | Как понимаем, что готово |
| --- | --- | --- |
| 1 · Доступ | Выбираем доступную нашему аккаунту модель и проверяем в кабинете остаток запросов в сутки, лимит в минуту и входных токенов в минуту. Запускаем сервер с ключом. | Видим выбранную модель в `/api/model-status`. Доступ провайдера и работу строгого JSON подтверждаем первым завершённым заданием. |

Проверяем обоснования по тексту на каждом языке и отношение к действиям оператора. Для N/A сверяем причину с условием критерия. Ожидаем «Нет» по старому правилу и «Да» по новому со ссылкой на эту реплику. Сверяем обе сохранённые карточки. Расхождение записываем для разбора. |

Для проверки качества сохраните на небольшой выборке независимые ответы человека и ссылки на реплики. При отсутствии эталона отдельно сообщите, что именно удалось проверить вручную. Неподтверждённые продуктовые факты по критерию 04 отмечайте для проверки по официальным материалам. [Разметка и метрики](PARTICIPANT_2_HANDOFF.md) · [Пример нового правила](contracts/checklists/chat-v2-greeting-only.example.json)

**Как распределить контрольный час.** Целевой график после выдачи группы — первые 5 минут на импорт, следующие 30 на оценку, ещё 15 на повторы и проверку, последние 10 на push и проверку ссылки. Скорость провайдера замерьте на DEV заранее. Согласуйте с участниками № 1 и № 3 ветку сдачи, кто покажет редактор и кто проведёт апелляцию на защите.

## Первая реальная оценка

Команды выполняются в PowerShell 7 из корня репозитория после установки зависимостей. Для уже реализованного подключения Google выберите доступную вашему проекту модель Gemini с поддержкой структурированных ответов и совместимыми параметрами. Проверяйте доступность и квоты в своём кабинете. Сервер обращается к модели, когда создаётся задание. [Получить ключ в AI Studio](https://aistudio.google.com/apikey) · [Настройка Gemini](PARTICIPANT_2_HANDOFF.md) · [Квоты Google](https://ai.google.dev/gemini-api/docs/rate-limits)

```powershell
pwsh -STA -NoProfile -File scripts/start-google-pair.ps1 -KeyDialog
```

Скрипт запрашивает ключ скрытым вводом и проверяет в каталоге Google, доступны ли `gemini-3.8-flash` и `gemma-3-27b-it` для этого проекта. Обе модели обращаются к одному сервису с одним ключом. Gemini получает JSON Schema, Gemma получает её вместе с инструкцией в пользовательской реплике. Сервер проверяет тот же контракт в обоих случаях. Запрос каталога не измеряет пропускную способность. Скорость, квоту, качество на RU/KZ/EN и доступность резерва проверяйте в своём проекте. Модели получают транскрипт; плеер предназначен для проверки записи человеком.

Во втором терминале из корня запустите `cd frontend`, затем `npm run dev`. Откройте DEV, выберите диалог и версию правил и нажмите «Оценить диалог». Ключ вводится в локальном окне запуска сервера. [Открыть первый чат](http://127.0.0.1:5173/analysis?group_id=DEV&conversation_id=p1-ru-001)

**Резерв OpenRouter.** При ошибке квоты, сети или временном сбое Gemini резерв получает тот же транскрипт и чек-лист. На Windows команда `.\.venv\Scripts\python.exe -m backend.app.connect_openrouter` открывает вход и проверяет бесплатный маршрут на учебном диалоге. Сервер проверяет JSON по полной схеме, ссылки на реплики и правила чек-листа. Записи попыток сохраняют фактическую модель. Для ручной конфигурации остаются переменные `CQA_FALLBACK_PROVIDER`, `CQA_FALLBACK_MODEL`, `CQA_FALLBACK_CONTEXT_TOKENS` и `OPENROUTER_API_KEY`. [Инструкция по подключению](PARTICIPANT_2_HANDOFF.md#резерв-через-openrouter-на-windows)

## Команды на сдачу

Из корня, в отдельном терминале, при запущенном API. Если сервер использует `CQA_DB_PATH`, задайте тот же путь здесь. В штатном сценарии используется `data/cqa.sqlite3`.

```powershell
$python = '.\.venv\Scripts\python.exe'
$model = (Invoke-RestMethod http://127.0.0.1:8765/api/model-status).model
& $python -m backend.app.submission status dev
& $python -m backend.app.submission run dev --model $model --mode external_api
& $python -m backend.app.submission check dev
```

Перед выдачей контроля сделайте push проверенного DEV. После выдачи задайте источник организаторов на сервере, получите группу и выполните команды.

```powershell
$group = Read-Host 'Выданный организаторами group_id'
$encoded = [Uri]::EscapeDataString($group)
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8765/api/groups/$encoded/import"
& $python -m backend.app.submission run prod --group-id $group --model $model --mode external_api
& $python -m backend.app.submission check prod --group-id $group
```

После успешной проверки добавьте соответствующий JSON в Git, сделайте коммит и push. Откройте файлы на GitHub именно в ветке, ссылку на которую получило жюри. Если передана ссылка на `main`, завершите слияние до стоп-кода. [Выгрузка, повторы ошибок и push](../results/README.md) · [Подключение источника](ZIP_INTEGRATION.md)
