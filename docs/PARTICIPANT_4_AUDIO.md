# Сверка пяти записей DEV

Сервер получил пять MP3 со страниц плеера организаторов. Для каждой записи проверен запрос диапазона первых 16 байт через маршрут приложения. Все пять ответов имели статус HTTP 206 и правильный общий размер. По всем пяти API выдал проверенные фрагменты.

Речь сопоставлена локально при помощи Vosk (small-ru 0.22). После нормализации регистра и «ё» выбранные последовательности из четырёх и более слов встречались ровно один раз и в распознанной записи, и в исходном транскрипте. В реестре сохранено 17 совпадений. ## Пауза в p4-ru-001

По исходному времени между системными событиями m0010 и m0012 прошло 14,56 с. Шестнадцать последних слов реплики m0008 заканчиваются в записи на 54,45 с. Уже с 65,81 с звучат последние три слова реплики m0013. Обе последовательности уникальны в данном транскрипте и записи. Между этими точками всего 11,36 с. Полный интервал 14,56 с туда не помещается. Точную длину вырезанного участка и единое смещение для остальных реплик по этим двум событиям определить нельзя.

## Плеер и доказательства

- Браузер получает запись через `GET /api/groups/{group_id}/conversations/{conversation_id}/audio`. Ответ поддерживает HEAD и один диапазон байтов, включая суффиксные диапазоны.
- `GET /api/groups/{group_id}/conversations/{conversation_id}/audio-anchors` возвращает проверенные позиции с `message_id` из transcript и полями `group_id`, `conversation_id`. Сервер сопоставляет SHA-256 загруженного медиаресурса и содержимого транскрипта с `backend/app/resources/audio_proof.json`. При изменении одного из них возвращаются `status: unverified` и пустой список. Новые записи доступны для воспроизведения, но требуют отдельной сверки.
- Сетевой сбой возвращает явную ошибку маршрута аудио. Карточка транскрипта остаётся доступной. Во время проверки встречались временные сбои соединения; повторный прогон всех пяти записей прошёл полностью.
- Маршрут плеера получает файл на сервере и передаёт браузеру байты. Разрешены HTTPS, точный список доменов и публичные IP. При каждом перенаправлении и переходе от HTML-плеера к файлу проверка повторяется. Сокет открывается на проверенный IP с проверкой TLS для исходного домена. Дополнительные разрешённые домены задаёт администратор сервера через `CQA_AUDIO_ALLOWED_HOSTS`.
- Кеш в памяти ограничен 64 МиБ и 15 минутами, один медиаресурс — 32 МиБ, HTML — 128 КиБ, вся цепочка загрузки ограничена пятью запросами и временным бюджетом. Для повторной проверки содержания по той же подписанной ссылке после изменения записи дождитесь истечения времени кеша либо перезапустите сервис.

Модуль добавляет маршруты к действующему team-v1. Исходная карточка ZIP по-прежнему возвращает audio_url. Компонент плеера может пользоваться отдельными маршрутами аудио и доказательств. Дополнительная разметка сохраняет прежние ID и баллы.
