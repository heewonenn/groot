# Участник 4 · Данные, записи и очередь оценок

Работа встроена в действующий `team-v1`. Общий чат — `DEV / p1-ru-001`, звонок — `DEV / p4-ru-001`. Ссылки на доказательства состоят из `group_id`, `conversation_id` и `message_id`. Нумерация сообщений начинается с единицы. Правила и баллы берутся из модуля участника № 1.

## Запуск

В корне установленной копии используйте два терминала:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8765
```

```powershell
cd frontend
npm run dev
```

На новом компьютере сначала выполните `pwsh -NoProfile -File scripts/setup.ps1`. Чтобы загрузить DEV, настройте серверный источник и нажмите «Импортировать набор» на экране диалогов. При недоступности источника используется CLI импорта ранее полученного локального снимка. [Подключение и импорт](ZIP_INTEGRATION.md).

- [Список диалогов](http://127.0.0.1:5173/conversations?group_id=DEV)
- [Первая реплика оператора общего чата](http://127.0.0.1:5173/conversations?group_id=DEV&conversation_id=p1-ru-001&message_id=p1-ru-001%3Am0010)
- [Сверенная фраза в звонке](http://127.0.0.1:5173/conversations?group_id=DEV&conversation_id=p4-ru-001&message_id=p4-ru-001%3Am0027)
- [Редактор участника № 1](http://127.0.0.1:5173/checklists)

Повторный импорт идентичного DEV сохраняет 65 диалогов и все 1 268 реплик. Изменение уже сохранённого текста в той же группе возвращает 409 и откатывает импорт. Исходные роли и время сохраняются. Лимит снимка по умолчанию 10 MiB; настройка `CQA_IMPORT_MAX_BYTES` применяется к локальному и удалённому JSON.

## Для участника № 2

Приложение принимает синхронный адаптер через `create_app(evaluator=...)` в `backend/app/main.py`. Сигнатура адаптера — `evaluate(evaluation_id, conversation, checklist_version, model_config) -> model_result`. Сервер передаёт сохранённый чек-лист и транскрипт без подписанного адреса записи. На выходе ожидается `model_result` из `docs/contracts/cqa-team-v1.schema.json` с теми же ID. Для сетевого вызова адаптер задаёт тайм-аут и бюджет попыток. Секреты провайдера задаются на сервере.

Сервер проверяет ссылки и диапазоны доказательств, принадлежность к группе, допустимые ответы и версию правил. Для завершённого результата он вызывает общий `calculate`, сохраняет карточку в SQLite и проверяет её по командной JSON Schema. У частичного результата нет полного итога. Доступность адаптера показывает `GET /api/capabilities`. До подключения модели новый запуск отвечает HTTP 503.

## Для участника № 3

На странице `/conversations` карточка открывает доказательство по составной ссылке. Аудиоплеер обращается к `GET /api/groups/{group_id}/conversations/{conversation_id}/audio`, а для навигации запрашивает `…/audio-anchors`. Поля `start_seconds` и `end_seconds` обозначают совпавшие слова. У непроверенных фраз отображается статус без вычисленного смещения. Маршрут записи поддерживает GET, HEAD и Range. [Проверенные переходы для всех пяти звонков](PARTICIPANT_4_AUDIO.md).

Готовая карточка оценки читается через `GET /api/evaluations/{evaluation_id}`. В ней разделены `model_result`, `original_result`, `final_result` и `review_history`. Открытие и решение апелляции в интерфейсе остаются в зоне ответственности участника № 3.

Внутри транзакции решения (`BEGIN IMMEDIATE` на соединении `team_data.connect()`) вызовите `services.evaluation_jobs.store_review(db, evaluation_id, decision)`. Передайте объект `review_decision` из team-v1 и следующую ревизию. Функция проверит принадлежность доказательств, вызовет расчёт участника № 1 по исходной версии правил и сохранит решение. При конфликте ревизии возвращается 409. Откат внешней транзакции отменяет и пересчёт, и историю.

## Как запускать набор

Один процесс FastAPI обслуживает очередь из двух рабочих потоков. Для создания задания с новой попыткой нужен уникальный заголовок `Idempotency-Key`. Пример тела для `POST /api/evaluation-jobs`:

```json
{"group_id":"DEV","conversation_ids":["p1-ru-001"],"checklist_version_id":"freedom-chat@1","model_config":{}}
```

Для звонков выбирайте `freedom-call@1`. Состояние и ошибки по диалогам показывает `GET /api/evaluation-jobs/{id}`. Повтор ключа и тела возвращает прежний ID. Другие параметры с этим ключом дают 409. Результат сохраняется после каждого диалога. После перезапуска сервера прерванные записи можно обработать через `POST /api/evaluation-jobs/{id}/retry`. Этот маршрут создаёт дочернее задание с новым ключом и выбирает только незавершённые или неуспешные записи. Экспорт доступен через `GET /api/evaluation-jobs/{id}/export`.

Синтетический адаптер используется в автотестах. Для измерения времени и стоимости реальной обработки DEV и контроля требуется провайдер участника № 2. Подготовленные ответы с режимом `demo` не участвуют в оценке точности модели.
