# Участник 2: модель, доказательства и измерение качества

Основная модель команды — Gemini 3.8 Flash через Google AI Studio. Скрипт подключает резервную Gemma 3 27B, если она доступна проекту.
В Windows запустите из корня `pwsh -STA -NoProfile -File scripts/start-google-pair.ps1 -KeyDialog`.
Скопируйте ключ кнопкой **Copy API key** в AI Studio, вставьте его в защищённое поле (Ctrl+V) и нажмите **Подключить**.
Без `-KeyDialog` доступен скрытый ввод в терминале. Журнал хранит название модели каждой попытки. Для проверки квоты
и качества нужен живой запуск. [Порядок проверки](PARTICIPANT_2_4_PLAN.md)

Если запуск не удался, диалог покажет причину. Последний этап проверки сохраняется локально в `data/google-startup.json`.
Если в каталоге доступна только одна из двух выбранных моделей, сервер может работать с ней. Активную модель показывает `/api/model-status`.
Для локальной смены модели можно сохранить рядом с базой файл `google-model.local.json` с полями `model` и `context_tokens`.
Например, для Gemini 3.8 Flash используйте `{"model":"gemini-3.8-flash","context_tokens":1048576}`. При запуске через скрипт размер контекста берётся из каталога Google. [Описание модели](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)

## Реализация

- evaluation/provider.py: интерфейс Provider и адаптер OpenAI Responses API.
  Конкретная модель не зафиксирована; другой сервис реализует тот же интерфейс
  generate(instructions, payload, schema, timeout) -> Reply.
- evaluation/gemini.py: Gemini generateContent по HTTPS через уже установленный httpx.
  Общие инструкции и JSON Schema передаются через systemInstruction и responseFormat;
  temperature/top_p/top_k не задаются. Токены ответа включают thoughtsTokenCount.
  Ответы с блокировкой, обрезанием или неожиданной структурой не становятся оценкой.
- evaluation/contract.py: версионированная инструкция, полный вход, схема ответа,
  дополнительная проверка доказательств и извлечение цитат из сохранённых реплик.
- evaluation/engine.py: адаптер Evaluator для JobRunner участника 4; одна основная
  попытка, один корректирующий повтор и один сетевой повтор с задержкой 0,5 с,
  всего максимум три вызова.
- evaluation/knowledge.py: локальные проверенные продуктовые фрагменты и
  детерминированный поиск; автоматического открытия ссылок нет.
- evaluation/store.py: отдельная таблица cqa_model_runs в общей SQLite.
- evaluation/quality.py и metrics.py: шаблоны независимой разметки и расчёт
  показателей по исходным AI-ответам до апелляций.
- model_app.py: подключение оценщика, статус конфигурации и API аудита.
- tests/test_model_evaluation.py: синтетические проверки адаптера и общей очереди.
- tests/test_gemini_evaluation.py: HTTP-фикстуры Gemini и интеграция с factory/очередью.

В модели нет собственной формулы баллов. Валидные ответы проверяет build_card,
который использует калькулятор участника 1. Частичная оценка не получает итог.

Вход содержит group_id, conversation_id, канал, язык, исходные message_id,
роли, время, тексты и всю неизменяемую версию чек-листа, включая значения и
описания ступеней. Подписанный audio_url и посторонние поля исключены.
Слишком большой вход отклоняется явно; обрезания транскрипта нет.

Проверяются полнота/уникальность критериев, типы, ступени, разрешение N/A,
обоснование и контекст N/A, ссылки в том же диалоге, порядок диапазона,
положение опорной реплики внутри диапазона, обязательный диапазон для absence.
Неизвестные ссылки на справочник и заявления об анализе аудио отклоняются.
Неразрешённый критерий требует объяснения и основания ручной проверки.
Простое существование ID ещё не доказывает смысловую верность вывода:
это отдельно проверяется при разметке.

Модель не получает инструментов, способных исполнять команды или открывать URL.
Транскрипт и справочник обозначены как недоверенные данные.
Наличие инструкции против prompt injection не является доказательством её
устойчивости: реальные провокационные примеры ещё нужно проверить на выбранной модели.

## Альтернативный профиль Gemini 3.8 Flash

Ключ создаётся в https://aistudio.google.com/apikey и вводится только на backend.
Наличие ключа не означает наличие квоты или бесплатного тарифа. Проверьте проект,
доступ к модели, Billing Tier и Rate limits в AI Studio. Не отправляйте личные или
конфиденциальные данные в бесплатный сервис: используйте синтетические либо
действительно обезличенные данные без конфиденциального содержания.

В PowerShell (переменные действуют в этом окне; .env автоматически не читается):

```powershell
$env:CQA_MODEL_ENABLED = '1'
$env:CQA_MODEL_PROVIDER = 'gemini'
$env:CQA_MODEL = 'gemini-3.8-flash'
$env:CQA_CONTEXT_TOKENS = '128000'
$env:CQA_GEMINI_THINKING_LEVEL = 'medium'
Remove-Item Env:CQA_INPUT_USD_PER_MILLION, Env:CQA_OUTPUT_USD_PER_MILLION -ErrorAction SilentlyContinue
$cqaSecret = Read-Host 'Gemini API key' -AsSecureString
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', $cqaSecret).Password
.\.venv\Scripts\python.exe -m uvicorn backend.app.model_app:create_configured_app --factory --host 127.0.0.1 --port 8765
```

128000 — выбранный лимит проекта, ниже входного лимита модели 1048576.
При provider=gemini и отсутствии CQA_MODEL используется gemini-3.8-flash.
CQA_GEMINI_THINKING_LEVEL допускает только low, medium, high; default=medium.
Для других Gemini-моделей совместимость параметров отдельно не подтверждалась.
Читается только GEMINI_API_KEY: GOOGLE_API_KEY и OPENAI_API_KEY не подменяют его.
При ошибке Gemini автоматического переключения на платный OpenAI нет.

GET /api/model-status должен вернуть configured=true, ready=true, provider=gemini.
Это проверка локальной конфигурации, не проверка ключа или доступности Google.
Первый POST /api/evaluation-jobs действительно отправляет транскрипт поставщику.
Начните с одного синтетического чата, затем проверьте звонок по транскрипту и RU/KZ/EN.

Без настроенного резерва HTTP 429 даёт provider_rate_limit без немедленного повтора:
лимит может быть дневным. Проверьте квоту и позже явно создайте новое задание
с новым Idempotency-Key. Повтор прежнего ключа возвращает прежнее задание.
Сетевые ошибки/408/5xx используют существующий единственный ограниченный повтор.
Новый API-ключ того же проекта не увеличивает квоту; вся очередь по-прежнему имеет
два worker. Для бесплатного теста отправляйте по одному диалогу и соблюдайте квоту.

Резерв задаётся отдельно через `CQA_FALLBACK_PROVIDER`, `CQA_FALLBACK_MODEL` и
`CQA_FALLBACK_CONTEXT_TOKENS`. При ошибке квоты или временном сетевом сбое очередь
может использовать указанный резервный сервис. Отказ по содержимому и ошибка
авторизации завершают попытку без переключения. Общий бюджет остаётся равным трём
вызовам. Для OpenRouter нужен серверный ключ и конкретная бесплатная модель,
поддерживающая строгую схему. [Проверка резервного сервиса и план сдачи](PARTICIPANT_2_4_PLAN.md)

Стоимость остаётся null, пока явно не заданы обе ставки CQA_*_USD_PER_MILLION.
Если вы подтвердили бесплатную квоту проекта, можно задать обе ставки равными 0.
При смене поставщика/тарифа сбросьте старые ставки. Расчёт приблизительный:
использует promptTokenCount и candidatesTokenCount + thoughtsTokenCount, включая
корректирующие ответы; не учитывает скидки кеша и дополнительные тарифные условия.
Неизвестная/некорректная статистика не превращается в нулевую стоимость.

## Переключение на OpenAI

Альтернативный адаптер использует OpenAI Responses со Structured Outputs.
Это не рекомендация определённой модели и не проверка её фактической точности.
Модель должна поддерживать этот формат API. Реальную совместимость нужно подтвердить
первым разрешённым запросом. Документация формата:
https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses

В PowerShell 7 задайте серверные переменные окружения. .env автоматически не читается.
Ключ не отправляйте в чат и не помещайте в VITE_*.
При отсутствии CQA_MODEL_PROVIDER сохраняется прежнее поведение: provider=openai.
Явно выбирайте поставщика; сбросьте/обновите ставки стоимости перед переключением.

    $env:CQA_MODEL_ENABLED = '1'
    $env:CQA_MODEL_PROVIDER = 'openai'
    $env:CQA_MODEL = Read-Host 'ID выбранной модели'
    $env:OPENAI_API_KEY = Read-Host 'API-ключ' -MaskInput
    $env:CQA_CONTEXT_TOKENS = Read-Host 'Допустимый размер контекста выбранной модели'
    .\.venv\Scripts\python.exe -m uvicorn backend.app.model_app:create_configured_app --factory --host 127.0.0.1 --port 8765

Включение конфигурации само по себе не отправляет диалоги. Вызов создаётся при
POST /api/evaluation-jobs. Такой запуск передаёт транскрипт и правила выбранному
поставщику и может расходовать средства; его выполняют после согласования сервиса и бюджета.

CQA_CONTEXT_TOKENS обязателен и не должен превышать подтверждённый контекст модели.
Перед запросом применяется консервативная проверка: UTF-8 размер входа, инструкции
и схемы, резерв 4096 для обёртки/коррекции и max_output_tokens.
Это верхняя оценка токенов для BPE, а не точный токенизатор; она может отклонять
вход, который фактически поместился бы. Ошибка поставщика не приводит к усечению текста.

Дополнительные настройки:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| CQA_REQUEST_TIMEOUT | 60 | тайм-аут сетевой операции, секунды, максимум 120 |
| CQA_TOTAL_TIMEOUT | 150 | бюджет оценки между попытками, секунды, максимум 360 |
| CQA_MAX_INPUT_CHARS | 180000 | дополнительный предел размера полного входа |
| CQA_MAX_OUTPUT_TOKENS | 12000 | бюджет ответа; максимум 32000 |
| CQA_KNOWLEDGE_PATH | не задан | локальный JSON официальных фрагментов |
| CQA_INPUT_USD_PER_MILLION | не задан | подтверждённый тариф входных токенов |
| CQA_OUTPUT_USD_PER_MILLION | не задан | подтверждённый тариф выходных токенов |

HTTPX ограничивает отдельные сетевые операции; это не принудительное завершение
потока ровно по настенным часам. Бюджет проверяется до/после вызова и при чтении
ответа; опоздавший ответ не принимается. На выбранной модели нужно измерить фактические задержки.
429/408/5xx и сетевые ошибки получают один повтор. Отказ, ошибка авторизации и
неполный ответ не превращаются в демонстрационную оценку.

Стоимость — только оценка по заданным тарифам, без скидок за cached tokens,
налогов и поправок провайдера. Если хотя бы у одной попытки неизвестны токены
или тарифы не заданы, общая стоимость null. Это не нулевой расход.
Каждая попытка хранит длительность, доступные токены, модель и код ошибки.

Настройки задания provider/model/prompt_version/knowledge_version могут только
подтвердить серверную конфигурацию. Произвольная смена сервиса, temperature,
top_p, seed и audio_version сейчас возвращает settings_not_supported.
Параметры нельзя молча игнорировать. Для других режимов нужен явный адаптер.

## API для участников 3 и 4

Штатный запуск:

    POST /api/evaluation-jobs
    Idempotency-Key: <новый уникальный ключ>

    {
      "group_id": "DEV",
      "conversation_ids": ["p1-ru-001"],
      "checklist_version_id": "freedom-chat@1"
    }

Получите job_id, затем используйте существующие GET /api/evaluation-jobs/{job_id}
и GET /api/evaluations/{evaluation_id}. Карточка остаётся team-v1.
Повтор с тем же ключом и параметрами не делает новую платную оценку.

Дополнительные маршруты:

| Маршрут | Назначение |
| --- | --- |
| GET /api/model-status | готовность, модель, версия инструкции/справочника, отсутствие анализа аудио |
| GET /api/evaluation-runs?group_id=DEV&conversation_id=p1-ru-001 | последние 100 запусков, включая неудачные |
| GET /api/evaluation-runs/{evaluation_id} | безопасные метаданные попыток, времени, токенов и стоимости |
| GET /api/evaluation-runs/{evaluation_id}/evidence | цитаты и диапазоны из сохранённого входа |

Для проваленного задания участник 4 не возвращает evaluation_id в item.
Его диагностический запуск можно найти через список по группе и диалогу.
Полные входы и ответы хранятся локально в приватной SQLite; статусный API
не отдаёт полный снимок, API-ключ или тело ошибки поставщика.
Снимки содержат транскрипты: сам файл SQLite нельзя публиковать.

Основные коды: model_disabled, model_configuration_missing, model_configuration_invalid,
settings_not_supported, input_invalid, input_too_large, context_budget_exceeded,
answer_json_invalid, answer_schema_invalid, answer_rules_invalid,
answer_scope_invalid, answer_knowledge_invalid, provider_auth, provider_refused,
provider_incomplete, provider_network, provider_transient, provider_rate_limit, evaluation_deadline.
По answer_* разрешён только один корректирующий вызов.
После перезапуска незавершённый аудит получает interrupted; повторной оплаты
автоматически не происходит.

Интерфейс участника 3 из PR #5 отображает историю, время, стоимость и причины
из нового API. Для Gemini добавлено понятное сообщение о provider_rate_limit.
Текущий общий /api/capabilities.product_reference остаётся false;
наличие настроенного справочника проверяется через /api/model-status.
Участнику 4 нужно использовать новый factory либо передать настроенный ModelEvaluator
в свой create_app. Не запускать одновременно два сервера на 8765.

## Справочник

Импортируется локальный JSON с source_version_id, reviewed_by, as_of (YYYY-MM-DD)
и fragments. Каждый фрагмент содержит fragment_id, title, source_url и text.
Источник должен быть официальным и проверенным человеком.
Версия и хеш всего справочника сохраняются; в запрос попадают максимум восемь
совпавших фрагментов с их ID и датой. Изменение текста под прежним ID видно по хешу.

Поиск лексический: он не гарантирует RU/KZ/EN синонимы и полноту извлечения.
При отсутствии решающего продуктового факта инструкция требует unresolved.
Сервер проверяет существование источника и ссылки, но сам по себе не доказывает,
что текст фрагмента подтверждает конкретное утверждение модели.

## Поэтапная проверка вашей роли

1. Выбрать поставщика, фиксированную версию модели, поддерживаемый формат,
   размер контекста и бюджет. Подготовить официальные продуктовые материалы.
2. Запустить общий чат p1-ru-001. Проверить реальную карточку, все критерии,
   роли, N/A, источники и переходы по message_id. Зафиксировать evaluation_id.
3. Разобрать p4-ru-001 с freedom-call@1. У этой реализации только транскрипт
   и timestamps. Акустические выводы не поддерживаются.
4. Проверить минимум по одному чату RU/KZ/EN. Короткие кандидаты:
   p1-ru-025, p1-kz-001, p1-en-001. Общий RU-чат для интеграции остаётся p1-ru-001.
   Особое внимание критерию 03: общий продуктовый вопрос и обязательная
   идентификация — разные ситуации.
5. В p1-ru-014 совместно с участником 1 сохранить новую версию критерия 01:
   убрать требование представиться, оставив приветствие. Повторить настоящий
   inference. Сверить ожидаемые «Нет»/«Да», ту же реплику и сохранность старой карточки.
   Затем добавить новый критерий и повторить. Синтетические тесты подтверждают
   передачу изменений, но не доказывают смысловое поведение будущей модели.
6. Независимо разметить развитие и отложенную часть. Не читать ответы модели
   до фиксации человеческих меток. Для спорных случаев нужен второй проверяющий.
7. После фиксации инструкции прогнать отложенную часть и повторные запуски
   неоднозначных примеров. Отдельно проверить ссылки и смысл доказательств.
8. Измерить 10 транскриптов и весь DEV: фактическое время, ошибки, повторы,
   токены, подтверждённую стоимость. Цель 10 транскриптов за 10 минут пока не измерена.
